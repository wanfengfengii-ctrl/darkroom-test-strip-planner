# 暗房试条计算器（Darkroom Test Strip）

暗房放大制作试条时，每“半档”曝光相差的是 **√2 ≈ 1.414 倍**，而不是固定增减若干秒。
本工具输入基准曝光秒数与档位区间，立即生成**从左到右等宽**的试条图形和秒数序列，
帮助临场快速复核，避免把档位差误算成等差秒数。

纯前端单页应用：TypeScript + React + Vite + CSS，**无后端、无任何外部服务调用**，
所有输入与计算结果只存在于当前浏览器页面中。

## 参数说明 与 启动 / 验收

### 参数（全部字段都有就地校验，非法即清空结果）

| 参数 | 取值范围 | 含义 |
| --- | --- | --- |
| 基准曝光秒数 `base` | `0.1` ～ `300.0` | 0 档位置使用的曝光时间（秒） |
| 起始档位 `start` | `-3.0` ～ `+3.0` | 最左一格的档位，**必须小于**结束档位 |
| 结束档位 `end` | `-3.0` ～ `+3.0` | 最右一格的档位 |
| 分格数 `N` | `3` ～ `9` 的整数 | 等宽分格数量 |

任一输入为空、非有限数字（如 `abc`、`1e999`）、超范围，或起始不小于结束时，
页面会立即在对应字段下方红字报错，同时**清除旧的试条图形、秒数序列与复制内容**；
修正后图形立即重新出现。

### 计算规则

- 第 i 格档位（i = 0 … N−1）：`start + i × (end − start) / (N − 1)`
- 第 i 格曝光秒数：`base × 2^档位`
- 秒数按**十进制四舍五入保留一位小数**并显示尾随零（如 `14.1`、`10.0`）
- 每格显示：序号（1 起）、档位（两位小数，如 `0.50`）、秒数（如 `14.1秒`）

示例：基准 10 秒、档位 −1 到 +1、5 格 →

| 序号 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| 档位 | −1.00 | −0.50 | 0.00 | 0.50 | 1.00 |
| 秒数 | 5.0 | 7.1 | 10.0 | 14.1 | 20.0 |

相邻半格的倍率 14.1 / 10 ≈ **1.414**，而秒数差（4.1 与 5.9）并不相等——这正是
不能用“固定增减秒数”代替档位的原因。

「复制秒数序列」按钮把**按视觉顺序（从左到右）**排列的制表符分隔秒数写入剪贴板，
例如 `5.0⇥7.1⇥10.0⇥14.1⇥20.0`，可直接粘贴到电子表格的一行。

### 累积遮挡操作单（秒表逐段动作）

试条下方还会生成一张「累积遮挡操作单」，把递增曝光的各格总时长翻译成暗房中
**逐段遮挡**的秒表动作：第 1 步对全纸曝光，之后每步用遮挡板遮住左侧已经完成的格子，
只对余下区域继续曝光。任何一格收到的曝光都等于“到该步为止各段之和”。

换算规则（全部以**未四舍五入**的精确曝光为目标，禁止从页面上一位小数显示值反推）：

1. 各格累计目标 = `base × 2^档位`（与试条公式相同，但不做一位小数取整）；
2. 首段增量 = 第一格目标；后续各段增量 = 相邻两格目标之差；
3. 增量 ×10 换算成 0.1 秒刻度：先给每段分配**向下取整**的刻度，
   再把剩余刻度按各段的小数余量**从大到小**逐个补发；余量相同时**左侧较早步骤优先**
   （最大余额法，保证各段刻度之和严格守恒）；
4. 总刻度 = 最高曝光目标 ×10 后按十进制四舍五入。

以默认参数（基准 10 秒、−1～+1 档、5 格）为例：

| 步骤 | 曝光区域 | 本段秒数 | 累计秒数 |
| --- | --- | --- | --- |
| 1 | 全纸（不遮挡） | 5.0 | 5.0 |
| 2 | 遮住左侧已完成第 1 格，曝光余下 4 格 | 2.1 | 7.1 |
| 3 | 遮住左侧已完成第 1～2 格，曝光余下 3 格 | 2.9 | 10.0 |
| 4 | 遮住左侧已完成第 1～3 格，曝光余下 2 格 | 4.1 | 14.1 |
| 5 | 遮住左侧已完成第 1～4 格，曝光余下 1 格 | 5.9 | 20.0 |

各段合计 **20.0 秒**，与最右一格的累计曝光一致。「复制操作单」按钮复制带
**步骤／曝光区域／本段秒数／累计秒数**表头的制表符文本，可直接粘贴到表格；
它与原「复制秒数序列」相互独立，原复制内容保持不变。

当某一段增量不足 0.1 秒、按上述规则分到 **0 刻度**时（例如基准 0.1 秒跨 −3～+3 档），
该参数无法在 0.1 秒精度下形成独立遮挡步骤：操作单表格与复制入口会就地隐藏，
并红字说明原因及涉及的步骤；**基础试条与秒数序列仍正常显示和复制**。
输入一旦非法，操作单与试条一起清空；修正为合法输入后立即重算。

### 启动（Docker Compose）

需要 Docker 24+ 与 Docker Compose v2：

```bash
docker compose up --build
# 打开 http://localhost:5173 （Vite 开发服务，带热更新）
```

停止：`Ctrl+C` 后执行 `docker compose down`。

### 验收（一次性 verify 服务）

`verify` 服务在已内置 Chromium 的 Playwright 镜像中**一次性**运行
Vitest 单元测试与 Playwright 端到端测试，结束后自动退出：

```bash
docker compose run --rm --build verify
```

端到端测试会在容器内自动执行 `npm run build` 并用 Vite 预览服务启动页面，
覆盖：半档 1.414 倍附近的结果、等宽分格、就地错误反馈、非法输入时图形消失、
修正输入后图形重新出现、复制按钮的制表符分隔内容，以及累积遮挡操作单的
逐段/累计秒数、操作单复制、0 刻度反馈与合法输入下的即时重算。

## 不用 Docker 的本地开发

```bash
npm ci
npm run dev          # http://localhost:5173

npm run build        # 类型检查 + 生产构建到 dist/
npm run preview      # 预览生产构建

npm run test:unit    # Vitest 单元测试
npx playwright install --with-deps chromium   # 首次运行 E2E 前安装浏览器
npm run test:e2e     # Playwright 端到端测试（会自动 build 并启动预览）
```

## 目录结构

```
src/
  lib/strip.ts        试条计算、校验与累积遮挡操作单（最大余额法分刻度）纯函数
  lib/strip.test.ts   Vitest 单元测试
  App.tsx             页面：表单、就地报错、等宽试条、遮挡操作单与两处复制
  main.tsx / styles.css
test/e2e/app.spec.ts  Playwright 端到端测试

docker-compose.yml    web（开发服务）与 verify（一次性验收服务）
```

## 隐私说明

应用不收集、不发送任何数据：没有分析脚本、没有外部网络请求，业务数据仅保存在
浏览器内存中的 React 状态里，刷新或关闭页面即消失。
